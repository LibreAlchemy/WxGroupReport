# 报告结果审计规则（Skill 自包含）

本规则用于 `trajectory-result-evaluation`，用于校验报告产物是否与分析结果一致。

## 1. 目标

在流程轨迹审计之外，增加“报告内容正确性”审计，重点判断：

1. 报告结构是否完整。
2. 数据概览是否与分析 JSON 一致。
3. Top10 排行是否与分析结果一致。
4. 低质成员清单是否与分析结果一致。
5. （可选）报告文件哈希是否与插件记录一致。

## 2. 输入产物

- 报告文件：`output/test-run/report.md`（默认）
- 分析文件：`output/test-run/analyze-messages.json`（默认）
- 报告产物追踪（可选）：`.opencode/traces/report_artifacts.latest.jsonl`

## 3. 必须检查项

### 3.1 结构完整性

报告需包含以下章节：

- `## 数据概览`
- `## 活跃度排行榜 (Top10)`
- `## 本期精彩内容`
- `## 低质成员名单`

### 3.2 数据概览一致性

从报告中提取以下数值，并与 `analyze-messages.json` 对比：

- `总成员数` == `len(memberScores)`
- `活跃成员数` == `count(messageCount > 0)`
- `低质成员数` == `len(lowQualityMembers)`
- `精彩内容数` == `len(highlights)`

### 3.3 Top10 一致性

预期 Top10 由 `memberScores` 按 `messageCount` 降序取前 10。

每行至少校验：

- 成员名
- 发言数
- 平均分（按一位小数比对）

### 3.4 低质成员一致性

从报告 `## 低质成员名单` 提取成员条目，并与 `lowQualityMembers` 比对：

- 条目数量一致
- 前若干条成员名顺序一致（用于快速发现渲染偏差）

### 3.5 报告哈希一致性（可选）

若存在产物追踪日志且命中同一报告路径：

- `sha256(report.md)` 必须等于追踪日志中的 `sha256`

若无追踪日志，则记为“可选项缺失”，不作为硬失败。

## 4. 评分建议

建议权重：

- 结构完整性：15%
- 数据概览一致性：35%
- Top10 一致性：20%
- 低质成员一致性：20%
- 哈希一致性：10%

## 5. 通过标准

满足以下条件判定 `passed=true`：

1. 必要文件存在且可解析。
2. 无结构缺失。
3. 数据概览无不一致。
4. Top10 无不一致。
5. 低质成员无不一致。

哈希一致性在无追踪记录时可降级为告警，不强制失败。
