# Agent 驱动文档规范

> 📅 创建日期: 2026-02-02  
> 🎯 目标: 定义 AI Agent 可解析、可执行的文档体系  
> 📌 版本: V2.0

---

## 核心理念

**文档是给 Agent 看的，驱动 Agent 行动。**

- Agent 开发前必须先看「需求清单」了解任务
- Agent 开发前必须先看「问题排查」避免踩坑
- 每个文档有元数据，Agent 可解析状态和依赖
- 文档流转有明确规则

## 🤖 Agent 行为规则

### 开发前必做（重要！）

```
1. 读取 docs/开发/需求清单/ 下的文档
   → 了解要开发什么、验收标准、优先级
   
2. 读取 docs/开发/问题排查/ 下的文档
   → 了解历史踩坑，避免重复犯错
   
3. 读取相关的 技术/系分/ 文档
   → 了解技术方案和设计决策
```

### 开发后必做

```
1. 更新 docs/开发/需求清单/ 中的任务状态
2. 创建 docs/开发/已实现功能/ 记录
3. 如果遇到问题，创建 docs/开发/问题排查/ 记录
```

## 📝 文档元数据规范

每个文档必须包含 YAML front-matter：

```yaml
---
type: 需求清单           # 文档类型
stage: active           # 状态: draft/review/approved/active/completed/archived
feature: 群聊分析工具    # 所属功能
version: "1.0"

owner: Kyle             # 负责人
created: 2026-02-02
updated: 2026-02-02

# 依赖关系（可选）
depends_on: []
blocks: []
---
```

### 状态定义

| stage | 含义 | 适用文档 |
|-------|------|----------|
| draft | 草稿 | 所有 |
| review | 评审中 | BRD/PRD/系分/测试分析 |
| approved | 已通过 | BRD/PRD/系分/测试分析 |
| active | 进行中 | 需求清单 |
| completed | 已完成 | 需求清单/已实现功能 |
| archived | 已归档 | 所有 |

## 🔄 文档流转

### 团队协作流程

```
业务方 → BRD(业务需求)
           ↓ 评审通过
@莫 → PRD(产品需求)
           ↓ 评审通过
@Kyle → 系分(技术设计) + 需求清单(任务拆解)
           ↓ 评审通过
@Napstablook → 排期
           ↓
@Kyle @七里香 → 开发执行
           ↓
@seasyec → 测试验收
           ↓
         上线
```

### Agent 开发流程

```
1. 读取「需求清单」→ 选择任务
2. 读取「问题排查」→ 了解历史坑
3. 读取「系分」→ 了解技术方案
4. 开发实现
5. 更新「需求清单」状态
6. 创建「已实现功能」记录
7. 如有问题，创建「问题排查」记录
```

## ✅ 验收标准格式

文档中使用 checkbox，Agent 可解析：

```markdown
- [ ] AC-001: 未完成
- [x] AC-002: 已完成
- [-] AC-003: 不适用
- [!] AC-004: 失败
```
