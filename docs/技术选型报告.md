# 技术选型报告

## 1. 项目概述

基于 PRD 需求，开发一个群聊记录分析工具，核心功能包括：

| 模块 | 功能 |
|-----|------|
| 数据采集 | 导入 JSON/JSONL 格式的微信群聊记录 |
| AI 分析 | 消息评分（4维度）、成员画像、内容分类、隐私过滤 |
| 报告生成 | 活跃度排行、精彩内容提取、低质成员名单、长图 + HTML |
| 辅助决策 | 提醒文本生成、清退名单、历史报告管理 |

### PRD 核心评分体系

| 维度 | 权重 | 说明 |
|-----|------|------|
| 信息密度 | 30% | 实质性信息、观点、知识分享 |
| 互动价值 | 25% | 推进话题、回应问题 |
| 知识贡献 | 25% | 技术见解、经验总结 |
| 内容完整度 | 20% | 消息长度、完整性 |

> 特殊规则：纯表情包、单字回复、刷屏重复内容均为 **0分**

## 2. 数据格式分析

### 2.1 源数据格式

| 格式 | 文件 | 特点 |
|-----|------|------|
| JSON | `xxx.json` | 完整结构：chatlab/meta/members/messages |
| JSONL | `xxx.jsonl` | 流式读取，通过 `_type` 区分类型 |

### 2.2 实际数据样本

从 `group/麦田怪圈.json` 采集的实际数据结构：

```json
{
  "chatlab": {
    "version": "0.0.2",
    "exportedAt": 1770093376,
    "generator": "WeFlow"
  },
  "meta": {
    "name": "[群组名称]",
    "platform": "wechat",
    "type": "group",
    "groupId": "[群组id]",
    "groupAvatar": "[群组头像链接]"
  },
  "members": [...],
  "messages": [...]
}
```

JSONL 格式（流式）：
```jsonl
{"_type":"header",...}
{"_type":"member",...}
{"_type":"message","sender":"wxid_xxx","content":"消息内容","timestamp":1769913971}
```

### 2.3 消息字段说明

| 字段 | 类型 | 说明 |
|-----|------|------|
| `_type` | string | header/member/message (仅JSONL) |
| `sender` | string | 发送者 wxid |
| `accountName` | string | 发送者昵称 |
| `timestamp` | int | Unix 时间戳 |
| `type` | int | 0=文本, 1=图片, 5=表情 7=拍一拍 25=回复 80=入群 |
| `content` | string | 消息内容 |

### 2.4 样本数据统计

- **群聊名称**: 麦田怪圈
- **成员数量**: 约 100+ 人
- **消息类型**: 支持文本、图片、表情等
- **导出工具**: WeFlow

### 2.5 消息类型分析

基于 `group/麦田怪圈.jsonl` 的实际数据分析：

#### 2.5.1 JSONL `_type` 类型

| _type | 说明 | 数量 |
|-------|------|------|
| `header` | 导出文件头信息 | 1 |
| `member` | 群成员信息 | ~100 |
| `message` | 消息内容 | 600 |

#### 2.5.2 Message `type` 类型分布

| type | 类型 | 数量 | 占比 | 样本 |
|------|------|------|------|------|
| 0 | **文本消息** | 426 | 71.0% | "有没有大佬教一下，vibe coding..." |
| 1 | **图片** | 14 | 2.3% | [图片] |
| 5 | **动画表情** | 37 | 6.2% | [动画表情] |
| 7 | **链接/红包** | 7 | 1.2% | [链接] [用户B]给你发了一个现金红包！ |
| 25 | **回复消息** | 79 | 13.2% | "将近20w行代码了 难啊" |
| 27 | **名片** | 1 | 0.2% | [名片] |
| 80 | **入群通知** | 36 | 6.0% | "[用户A]"通过扫描二维码加入群聊 |

#### 2.5.3 类型处理策略

| type | 类型 | 处理策略 |
|------|------|---------|
| 0 | 文本消息 | **主要分析对象**，AI 评分核心 |
| 1 | 图片 | 可选 OCR 识别文字 |
| 5 | 动画表情 | 根据 PRD 应评为 **0分** |
| 7 | 链接/红包 | 特殊消息，酌情处理 |
| 25 | 回复消息 | 有上下文关联，优先分析 |
| 27 | 名片 | 较少，可忽略或单独统计 |
| 80 | 入群通知 | **不计入**成员活跃度统计 |

#### 2.5.4 关键发现

- **文本消息(type=0)** 占比 71%，是主要分析对象
- **动画表情(type=5)** 根据 PRD 规则应评为 0 分
- **系统通知(type=80)** 不应计入成员活跃度统计
- **回复消息(type=25)** 包含上下文，可提升分析准确性

## 3. 技术方向分析

### 3.1 编程语言方向

| 方向 | 优点 | 缺点 | 推荐指数 |
|-----|------|-----|---------|
| **Python** | AI 生态丰富、JSON 处理强、开发快 | 性能一般 | 5星 |
| Node.js | 前后端统一、图片处理方便 | AI SDK 较弱 | 3星 |
| Go | 性能高、编译打包简单 | 生态较少 | 3星 |
| Rust | 性能极强、内存安全 | 学习曲线陡峭 | 2星 |

**推荐方向: Python**

### 3.2 AI/LLM 能力方向

| 方向 | 成本 | 效果 | 适用场景 |
|-----|------|-----|---------|
| **Minimax-2.1** | 低 | 优秀 | **当前主力** - 评分、内容分类 |
| GLM-4.7 | 中等 | 优秀 | 备选模型 |
| Claude API | 中等 | 最强 | 复杂场景 |
| DeepSeek API | 低 | 不错 | 成本敏感时 |

**当前决策: Minimax-2.1** - 成本低、响应快，已购买 Coding Plan
**备选: GLM-4.7** - 智谱生态

### 3.3 数据存储方向

| 方向 | 类型 | 适用场景 |
|-----|------|---------|
| **SQLite** | 轻量文件数据库 | 首选 - 单文件部署 |
| JSON 文件 | 简单存储 | 小数据量 |
| PostgreSQL | 关系型数据库 | 多群聊、大数据量 |
| Redis | 内存缓存 | 频繁读写 |

**推荐方向: SQLite**

### 3.4 报告生成方向

| 方向 | 输出格式 | 推荐场景 |
|-----|---------|---------|
| **Pillow + textwrap** | 图片 | 长图分享 |
| **Jinja2 + weasyprint** | PDF | 正式报告 |
| **ECharts + HTML** | 交互式网页 | 数据可视化 |

**推荐方向: Pillow + Jinja2**

### 3.5 数据解析方向

| 方向 | 库/工具 | 说明 |
|-----|--------|------|
| **标准 json** | Python json | JSON 格式解析 |
| **ijson** | 流式解析 | 大文件 JSONL |
| **pandas** | 数据分析 | 统计计算 |

**推荐方向: json + ijson**

### 3.6 消息处理策略

| 策略 | 说明 | 适用场景 |
|-----|------|---------|
| **按发言者分组** | 批量处理同一用户消息 | AI 评分场景 |
| 时间窗口分批 | 按时间段切分 | 大数据量处理 |

**推荐方向: 按发言者分组**

### 3.7 白名单存储

| 方向 | 格式 | 说明 |
|-----|------|------|
| **TXT 文本** | 注释支持 | PRD 要求，支持 `# 注释` |

### 3.8 架构方案选择

本项目支持两种架构方案：

#### 方案 A: 传统 Python 架构（本地运行）

```
JSON/JSONL -> Python 脚本 -> Minimax-2.1 -> 报告
                     |
                SQLite 存储 (脱敏)
```

| 特点 | 说明 |
|-----|------|
| 数据存储 | 本地 SQLite 文件 |
| 处理方式 | Python 脚本本地执行 |
| 隐私性 | 数据不离开本地 |

#### 方案 B: MCP + Skills 架构（云端协作）

```
用户导出 -> Supabase MCP (存储) -> Skills (编排) -> Minimax-2.1 -> 报告
```

**Supabase MCP 能力：**
| 能力 | 功能说明 |
|-----|---------|
| database | 查询、插入、更新聊天记录 |
| storage | 存储导出文件和报告 |
| realtime | 消息变更实时通知 |
| auth | 用户认证管理 |

**Skills 能力：**
| Skill | 功能说明 |
|-------|---------|
| import-chat-data | 导入 JSON/JSONL 聊天记录 |
| analyze-messages | AI 分析消息，4维度评分 |
| generate-report | 生成可视化报告 |
| export-results | 导出结果 |

#### 架构方案对比

| 维度 | 方案 A (本地) | 方案 B (MCP+Skills) |
|-----|--------------|---------------------|
| 数据存储 | SQLite 本地 | Supabase 云端 |
| 处理方式 | Python 脚本 | Skills 自动化 |
| 数据同步 | 单设备 | 多设备实时 |
| 隐私性 | 高 | 中 (数据上云) |
| 历史对比 | 手动管理 | 自动版本管理 |

#### 推荐场景

| 场景 | 推荐方案 |
|-----|---------|
| 个人使用，隐私敏感 | 方案 A |
| 多群聊统一管理 | 方案 B |
| 团队协作，实时通知 | 方案 B |
| 一次性分析 | 方案 A |

**当前决策**: 初期 **方案 A** (Python 本地架构)
**后续演进**: 方案 B (MCP + Skills 云端协作)

## 6. 核心模块流程

### 6.1 数据采集流程
```
导入文件 -> 格式检测(JSON/JSONL) -> 解析消息 -> 结构化存储
```

### 6.2 AI 评分流程
```
批量消息(按发言者分组) -> 分批调用 Minimax-2.1 -> 评分结果 -> 聚合统计
```

### 6.3 精彩内容分类
```
正则提取链接 -> AI 判定金句/机会 -> Top10 筛选 -> 格式化输出
```

## 8. 风险与应对

| 风险 | 应对措施 |
|-----|---------|
| AI 成本过高 | 缓存评分结果、批量处理 |
| 隐私泄露 | 评分时可能调用云端，**存储时脱敏** |
| 格式兼容性 | 支持 JSON/JSONL 双格式 |
| 大文件处理 | 流式解析 (ijson) |
