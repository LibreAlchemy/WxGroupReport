# 精修规则（Refined Report Rules）

目标：在保留全量版 `output/report.md` 的前提下，产出精修版 `output/report_refined.md`。

## 处理范围
- 仅处理 `# 本期看点` 小节。
- 允许同步更新数据统计中的 `**精彩内容数**` 字段。
- 除 `# 本期看点` 与 `**精彩内容数**` 外，不修改其他统计字段。

## 必须遵守（硬规则）
1. 保留并维护以下标题结构（缺失则补齐，顺序保持）：
   - `# 本期看点`
   - `## 📚 公众号 & 文章`
   - `## 🤩 精选分享`
   - `## 💻 Github 项目`
   - `## 💡 原创心得`
2. 删除明显无效条目：
   - 标题为占位词：`文章`、`链接`、`link`、`article`（含两侧书名号时同样视为占位词）
   - 标题或内容含小程序特征：`小程序`、`微信小程序`、`miniprogram`、`mini program`、`wxapp`
3. 链接规则：
   - `精选分享`：仅保留 `http://` 或 `https://` 链接条目
   - `Github 项目`：仅保留 `github.com` 域名链接条目
   - `公众号文章`：仅保留无链接条目（文章标题用《》包裹）
4. 原创心得规则：
   - 删除空内容、纯符号、无信息量短句
   - 删除提问/求助型表达（如以“？”结尾，或出现“我比较好奇”“请问”“有没有人知道”等）
   - 优先保留判断/结论型观点（如“应/需/会/才是/最重要/应该/建议/避免”等表达）
5. 去重规则：
   - 有链接条目：按 URL 去重
   - 无链接条目：按“标题/内容 + 作者”去重

## 聊天价值筛选（统一口径）
目标：四个小节都以“对群聊讨论是否有贡献”为核心，不只看内容本身，还看其在聊天语境中的价值。

### 第一层：聊天贡献门槛（不满足直接淘汰）
- 是否属于以下任意一种：
  - 回应问题或补充上下文
  - 提供可执行建议/方案/路径
  - 推进讨论（提出新信息、新判断、新方向）
  - 对已有观点进行纠偏、对比或复盘
- 直接淘汰：
  - 纯态度表达（如“好/赞/哈哈/同意”）且无观点展开
  - 无信息增量的重复转发
  - 明显标题党或与群主题弱相关内容

### 第二层：多维评分（总分 0~10）
每条内容按 5 个维度评分，每项 0~2 分：

1. 讨论推进度：是否让话题更清晰/更深入
2. 可执行性：是否提供可落地做法（步骤/命令/实践建议）
3. 信息增量：是否提供新信息而非重复
4. 可信度：是否有可验证来源（链接/仓库/文档/案例）
5. 主题相关性：是否贴合本群核心话题

### 分数修正
- 噪音惩罚 `-2`：
  - 纯情绪、空泛结论、无背景无方法的短句
- 闭环加成 `+1`（适用于原创心得/精选分享）：
  - 同时包含“问题背景 + 分析 + 结论/建议”
- 观点加成 `+1`（仅原创心得）：
  - 明确表达可辩论的判断、取舍或策略建议

### 小节保留上限
- `output/report_refined.md` 不设条目上限。
- 精修时只做质量筛选、去重和格式规整，不因为数量达到固定阈值而截断。

### 排序与截断
- 先通过第一层门槛，再按最终得分降序排序，最后按小节上限截断。
- 同分时按以下优先级：
  1. 讨论推进度更高
  2. 可执行性更高
  3. 信息密度更高
  4. 更近期的条目优先

## 输出要求
- 输出文件：`output/report_refined.md`
- 保持 Markdown 格式规范，不引入额外章节。
- 标题之间保留空行。
- 不改写作者名。
- 精修完成后，必须回填 `**精彩内容数**`，其值等于“本期看点”实际展示条目总数（以 `- ` 列表项计数）。

## 执行建议
- 先复制 `report.md` 到 `report_refined.md`，再在副本上精修。
- 精修完成后，复查是否仍包含：`《文章》`、`小程序`、非 `github.com` 的 Github 条目。
