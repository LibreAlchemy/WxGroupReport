# 精修规则（Refined Report Rules）

目标：在保留全量版 `output/report.md` 的前提下，产出精修版 `output/report_refined.md`。

## 处理范围
- 仅处理 `# 本期看点` 小节。
- 允许同步更新数据统计中的 `**精彩内容数**` 字段，不修改其他统计字段。

## 必须遵守（硬规则）
1. 保留并维护以下标题结构（缺失则补齐，顺序保持）：
   - `# 本期看点`
   - `## 🔥 新闻热点`
   - `## 🤩 精选分享`
   - `## 💻 开源项目`
   - `## 💡 原创心得`
2. 删除明显无效条目：
   - 标题为占位词：`文章`、`链接`、`link`、`article`（含两侧书名号时同样视为占位词）
   - 标题或内容含小程序特征：`小程序`、`微信小程序`、`miniprogram`、`mini program`、`wxapp`
3. 链接条目必须保持原始标题文本，不得擅自重新拟定标题。
4. 各板块条目必须通过下方 `## 筛选规则`。
5. 去重规则：
   - 有链接条目：按 URL 去重
   - 无链接条目：按“标题/内容 + 作者”去重

## 筛选规则

内容按报告板块筛选。`新闻热点`、`精选分享`、`开源项目` 主要处理文章标题和链接类内容；`原创心得` 处理群成员发言内容。

### 🔥 新闻热点
- 只保留有明确新闻价值的链接新闻。
- 标题必须具体说明新闻事件、产品变化、行业动态或重要发布。
- 标题部分必须保持原始链接标题，不得改写。
- 链接必须可验证，且格式符合 `[标题](http://... 或 https://...) @作者`。
- 如果条目不构成新闻，但仍有文章、资料、案例或经验分享价值，优先移动到 `精选分享`，并按 `精选分享` 规则重新处理。
- 删除标题党、震惊体、营销推广、重复转发、无明确事实增量的条目。
- 删除没有链接且不能移入 `精选分享`、标题含混、无法判断新闻主题的条目。

### 🤩 精选分享
- 主要保留文章、文档、资料、案例、经验帖等可进一步阅读的分享。
- 允许两种格式：无链接文章 `《标题》 @作者`，或链接分享 `[标题](http://... 或 https://...) @作者`。
- 链接分享的标题部分必须保持原始链接标题，不得改写。
- 标题必须清晰，能说明分享内容。
- 优先保留能提供新信息、背景资料、实践经验、工具方法或可复用资料的条目。
- 删除标题为占位词、标题无法说明内容、营销推广、无信息增量的重复分享。
- 无链接文章必须能仅通过标题判断主题；否则删除。

### 💻 开源项目
- 仅保留 `github.com` 域名链接条目。
- 标题部分必须保持原始链接标题，不得改写。
- 标题必须能说明项目名称、用途、技术方向或解决的问题。
- 优先保留可直接复用、能补充工具链、框架、工程实践或学习资料的项目。
- 删除非 GitHub 链接、无法判断项目价值、纯推广、重复转发的条目。

### 💡 原创心得
- 删除空内容、纯符号、纯态度表达（如“好/赞/哈哈/同意”）且无观点展开的条目。
- 删除提问/求助型表达（如以“？”结尾，或出现“我比较好奇”“请问”“有没有人知道”等）。
- 删除空泛结论、无背景无方法的短句、无信息增量的重复表述。
- 优先保留回应问题或补充上下文的发言。
- 优先保留提供可执行建议、方案、路径、复盘、纠偏、对比或明确判断的发言。
- 优先保留判断/结论型观点（如“应/需/会/才是/最重要/应该/建议/避免”等表达）。

## 保留策略

### 小节保留上限
- `output/report_refined.md` 不设条目上限。
- 精修时只做质量筛选、去重和格式规整，不因为数量达到固定上限而截断。

### 总量保留底线
- 精修后的“本期看点”总条目数，必须至少保留原始 `output/report.md` 中 `**精彩内容数**` 的 40%。
- 计算方式：`min_keep = ceil(original_highlights_count * 0.4)`。
- 当严格质量筛选后的结果少于该下限时：
  - 仍需继续遵守硬规则和对应板块筛选规则（标题结构、去重、`github.com` 限制、去除占位词/小程序噪音等）。
  - 可以适度放宽非硬性筛选标准，回补更多有效条目，直到达到 `min_keep`。
  - 不允许为了凑数回填明显无效条目。

## 输出要求
- 输出文件：`output/report_refined.md`
- 保持 Markdown 格式规范，不引入额外章节。
- 标题之间保留空行。
- 不改写作者名。
- 精修完成后，必须回填 `**精彩内容数**`，其值等于“本期看点”实际展示条目总数（以 `- ` 列表项计数）。
- 精修完成后，必须同时确认该数量不小于 `ceil(original_highlights_count * 0.4)`。
- 精修完成后，必须确认不再包含：`《文章》`、`小程序`、非 `github.com` 的开源项目条目。
